# 정책 데이터 작성 안내

정책 자료의 수집 기준과 작성 이유를 기록합니다. 데이터 형식은 `docs/db-schema.md` 6장을 따릅니다.

## 1. 파일 구성

| 파일 | 용도 |
|---|---|
| `policies.json` | DB에 넣을 정책 데이터 |
| `{policy_key}_source.txt` | 정책별 공식 원문, 출처, 확인일 보관 |
| `README.md` | 공통 작성 규칙과 정책별 검토 사항 기록 |

원문 파일은 `{policy_key}_source.txt` 형식으로 작성합니다. 예를 들어 `P001_source.txt`는 `policies.json`의 `P001` 정책에 해당하는 원문입니다.

원문과 정리된 데이터를 쉽게 대조하기 위한 이름이며, 프로그램에서 요구하는 파일명은 아닙니다. 원문 파일 자체가 앱에 연결되는 것도 아닙니다.

`policy_key`는 정책별 고유 번호로 사용합니다. 등록 전 중복 여부를 확인하고, 등록 후에는 정책명이나 목록 순서가 바뀌어도 유지합니다.

## 2. 공통 작성 규칙

- 공식 기관의 자료를 사용하고, 출처 주소와 실제 확인일을 기록합니다.
- 원문과 요약은 구분합니다. `original_text`에는 출처를 표시한 정책 원문을 넣고, 작성자 메모는 넣지 않습니다.
- `category`와 `region`은 DB 명세에 있는 코드값을 사용합니다.
- 확인하지 못한 내용은 추측해서 채우지 않고 검토 사항에 남깁니다.
- `null`과 `[]`은 필드별 의미를 확인한 뒤 사용합니다. 특히 나이의 `null`은 현재 시스템에서 제한 없음으로 처리되므로 주의합니다.
- 쉬운 말 변환 전에는 `easy_text: null`, 검증 전에는 `easy_text_verified: false`로 둡니다.
- JSON에는 주석을 넣을 수 없으므로 작성 이유와 확인할 내용은 이 문서에 기록합니다.

## 3. P001 — 자립준비청년 자립수당 지급

- 상태: 정책 데이터 초안 작성 완료. 팀 검토 및 쉬운 말 변환·검증 전
- 원문 파일: `P001_source.txt`
- 분야: `living_cost`
- 지역: `전국`

### 주요 필드 작성 이유

| 필드 | 작성 내용과 이유 |
|---|---|
| `policy_key` | 첫 정책에 `P001`을 부여했습니다. 팀의 기존 데이터와 중복 여부는 확인이 필요합니다. |
| `category` | 매월 생활비 부담을 줄이는 현금 지원이므로 `living_cost`로 분류했습니다. |
| `region` | 전국 대상 정책입니다. 참고한 지자체의 지역으로 제한하지 않았습니다. |
| `source_url` | 서류 목록까지 확인할 수 있는 자립정보북 공식 게시물로 지정했습니다. 나머지 출처는 원문과 README에 남겼습니다. |
| `apply_url` | 직접 신청 화면으로 연결되는 주소를 확인하지 못해 `null`로 두었습니다. 현재 API에서는 신청 버튼이 숨겨집니다. 신청 메뉴 경로는 `apply_method`에 적었습니다. |
| `checked_at` | 자료의 게시일이 아닌 실제 확인일을 입력했습니다. |
| `required_docs` | 방문 신청용, 대리 신청용, 해당자만 제출하는 서류를 구분했습니다. 여러 서류 중 하나만 내면 되는 경우는 한 항목으로 묶었습니다. |
| `support_period` | ‘신청 후 5년’으로 일괄 작성하지 않고 보호종료 유형별 기준을 적었습니다. 지급 회차·중지·소급에 관한 세부 사항은 추가 확인이 필요합니다. |
| `easy_text` / `easy_text_verified` | 아직 쉬운 말 변환과 검증을 하지 않아 각각 `null`, `false`로 두었습니다. |
| `is_active` | 팀 검토 전 초안이므로 `false`로 두었습니다. 정책이 종료됐다는 의미는 아닙니다. |

### 연령 조건

자립수당은 현재 나이뿐 아니라 보호종료 당시 나이, 보호기간, 종료 후 경과기간 등을 함께 봐야 합니다. 사전신청과 심의 예외도 있어 현재 나이의 최솟값·최댓값만으로 표현하기 어렵습니다.

초안에서는 나이 필터 때문에 정책이 미리 제외되지 않도록 `age_min`과 `age_max`를 `null`로 두었습니다. 이는 **검색 처리 방식에 대한 제안이며, 정책에 나이 조건이 없다는 뜻은 아닙니다.**

현재 명세의 `null` 의미와 혼동될 수 있으므로 백엔드·AI 담당과 확인이 필요합니다. 합의 전까지는 `is_active: false`를 유지합니다.

### 추가 확인 및 협의 사항

1. **온라인 사전신청 대상**  
   복지로에는 아동복지시설이, 업무매뉴얼에는 아동복지시설과 가정위탁이 표기되어 있습니다. 가정위탁의 온라인 사전신청 가능 여부는 추가 확인이 필요합니다.

2. **교육·상담 증빙의 선택 범위**  
   자립정보북에는 교육 이수증 외에 국민연금공단 재무상담 확인서도 안내되어 있습니다. 금융감독원 과정은 ‘2026년 6월 중 도입’으로 기재되어 있어 실제 개설 및 인정 여부를 확인해야 합니다.

3. **조건부 서류의 체크리스트 처리**  
   현재 구조는 `required_docs`의 모든 항목을 서류 체크박스로 만듭니다. 대리 신청을 하지 않는 사람에게도 대리인 서류가 표시될 수 있으므로, ‘해당 없음’ 처리나 신청 방식별 목록 분리를 논의해야 합니다. 이 문제는 서류 진행률에 영향을 줄 수 있습니다.

4. **자료별 자격 조건 표현 차이**  
   재보호, 원가정 복귀에 따른 제외, 심의 예외 등의 표현이 자료마다 다릅니다. 원문은 각각 보관했으며, 개인의 최종 자격을 자동으로 확정하지 않도록 해야 합니다.

### 확인한 범위와 남은 작업

JSON 문법, 필수 키, 코드값, 서류 항목의 길이는 확인했습니다. 실제 DB 등록과 API 연동 테스트, 쉬운 말 변환 검증은 아직 진행하지 않았습니다.

다음 작업은 아래 순서로 진행합니다.

- 백엔드·AI 담당과 연령 필터 및 조건부 서류 처리 방식 확인
- 협의 결과에 따라 데이터와 README 수정
- 쉬운 말 변환문 작성 및 원문 대조 검증
- 검토 완료 후 `is_active` 변경 및 DB·API 연동 확인

서비스에 노출하려면 `is_active`와 `easy_text_verified`가 모두 `true`여야 합니다.
