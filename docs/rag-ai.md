# RAG·AI 담당 진행 상황 (김수정)

RAG·AI 담당(김수정)이 맡은 정책 질문 답변(RAG), 쉬운 말 변환·정책 요약, 신청서 작성 도우미, AI 상담·롤플레잉의 구현 내용과 현재 상태를 정리한 문서입니다.
자세한 실행 방법은 각 폴더의 README를 봅니다.

| 기능 | 폴더 | README |
|---|---|---|
| 정책 질문 답변 (RAG) | `src/rag/` | `src/backend/README.md` (RAG 연결 부분) |
| 쉬운 말 변환·정책 핵심 사실 요약 | `src/easytext/` | `src/easytext/README.md` |
| 신청서 작성 도우미·공고 검색 | `src/formguide/` | `src/formguide/README.md` |
| AI 상담·롤플레잉 | `src/coach/` | `src/coach/README.md` |

기능마다 구현 현황 → 미완성·보완 필요 사항 → 기술적 개선 방안 순서로 정리하고, 마지막에 전체 개발 일정을 둡니다.

## 1. 정책 질문 답변 (RAG)

### 구현 현황
- 정책 원문(업무매뉴얼·자립정보북·복지로)을 나눠 OpenAI 임베딩(`text-embedding-3-small`)으로 Chroma 벡터 DB에 저장
- 질문과 가까운 원문을 찾은 뒤 `gpt-4o-mini`가 그 원문만 근거로 답변
- 답변 문장마다 출처를 붙이고, "~합니다"체로 통일
- 할루시네이션 방지
  - 원문에 없는 숫자, 자격을 단정하는 표현이 들어간 답변은 걸러냄
  - 답변 끝에 "자세한 조건은 공식 원문에서 꼭 확인하시기 바랍니다." 안내
  - 관련 원문이 없는 질문(예: 날씨)은 `no_evidence`로 답하지 않음
- 용어 사전으로 질문의 쉬운 말을 정책 용어로 바꿔 검색 (예: "퇴소하고 매달 받는 돈" → 보호종료·매월·수당)
- RAG 모듈 전환 기능: `.env`의 `RAG_MODE`로 가짜 답변(`mock`)과 실제 답변(`real`)을 전환 (`src/backend/app/rag_client.py`)
- 하이브리드 검색: 질문 단어가 그대로 들어 있는 원문은 뜻 거리가 조금 멀어도(0.8까지) 근거로 인정하고, 벡터 순위와 키워드 순위를 합쳐 정렬
  - "청년"처럼 짧은 질문이 근거 없음으로 끝나던 문제 해결 (0개 → 여러 정책)
  - 한 정책이 근거 자리를 다 차지하지 않게 정책당 2개까지 먼저 채워, 비교할 수 있게 여러 정책이 카드로 나옴
- 답변 안전 검사가 문장 끝 "(1)" 같은 근거 표시도 근거 번호로 읽음 (번호 칸이 빠져 답변이 대체 문구로 바뀌던 문제 해결)

확인 결과 (실제 호출):

| 질문 | 결과 |
|---|---|
| 자립수당은 얼마나 받을 수 있어? | 월 50만 원, 매월 20일 지급 (출처 포함) |
| 대리인이 온라인으로 신청할 수 있나요? | 신청할 수 없음 (출처 포함) |
| 오늘 서울 날씨 어때? | 답변하지 않음 (`no_evidence`) |
- 테스트: RAG 연결 테스트(`src/backend/tests/test_rag_*.py`) 통과

### 미완성·보완 필요 사항
- 답변 정확도 정량 평가 전

### 기술적 개선 방안
- 평가 질문셋(일반 질문·조건 경계 사례·근거 없는 질문)으로 검색 정확도, 답변 정확도, 근거 없는 답변 비율 측정
- 하이브리드 검색 기준값(거리 0.65·0.8, 정책당 2개)을 평가 질문셋으로 조정
- 비슷한 두 정책의 근거를 섞어 답하는 경우가 있음 (예: 자립수당 신청 방법에 더미 정책 출처) → 문장마다 한 정책의 근거만 쓰게 검사 추가

## 2. 쉬운 말 변환 (7단계)

### 구현 현황
- 단계: L1(7~8세) · L2(9~10세) · L3(11~12세) · L4(13~14세) · L5(15~17세) · L6(18~19세) · L7(20세 이상)
  - 나이로 단계를 추천하고, 사용자가 직접 고를 수 있음
  - 단계마다 문장 길이, 쓸 수 있는 용어 등급, 핵심 요약 문장 수를 정함 (`src/easytext/levels.py`)
- 출력 구조: 핵심 요약 + 더 알아보기. 항목은 받는 것 / 받는 사람 / 받을 수 없는 경우 / 기간 / 신청 방법 / 서류 / 문의 / 확인 필요
- 문장마다 근거가 된 원문 번호를 달게 해서, 원문 문장 하나하나가 빠짐없이 쓰였는지 확인
- 자동 검사 (`src/easytext/checks.py`)
  - 원문 문장 누락, 숫자·날짜·경계 단어(이상·이내·이후 등)
  - 조건부 서류의 조건, 우편·팩스 신청 조건, 신청 주체(본인·대리인·시설종사자), 부정 표현(불가·제외·중지)
  - 단계별 용어 등급, 문장 길이, "~합니다"체
- 2차 검수: 다른 모델(`gpt-4o`)이 원문과 비교해 뜻이 바뀌거나 빠진 곳을 찾음
- 뜻을 바꾸지 않는 자동 보정 (`src/easytext/convert.py`)
  - 어려운 용어를 사전에 정한 쉬운 표현으로 바꿈
  - 조건이 빠진 서류·우편 신청 문장에 원문 조건을 붙임
  - 핵심 요약이 길면 문장 단위로 더 알아보기로 옮김
  - 표현만 다른 반복 문장 정리 (더 자세한 문장을 남김)
  - 빠진 원문 문장만 따로 다시 변환해 채움
  - 끝까지 통과하지 못하면 지적이 가장 적은 시도를 결과로 냄
- 어려운 용어는 문장 안에 풀이를 넣지 않고 용어 풀이 목록(`terms`)으로 따로 내보냄
- 결과: 자립수당(P001) 7단계 모두 자동 검사·2차 검수 통과 (`data/easy_text/P001.json`, 아직 `verified: false`)
  - 가장 어려운 L1도 세 번 연속 변환해서 세 번 모두 통과
- 테스트: 85개 통과

### 정책 핵심 사실 추출·카드 요약 (`src/easytext/facts.py`)
- 원문에서 대상·제외·지원 내용·기간·신청 방법·서류를 짧은 구절로 먼저 뽑고, 원문과 대조해 검사
  (원문에 없는 숫자, 빠진 원문 문장, 숫자·경계 단어·부정 표현 누락, 출처 비교 메모, 문장을 중간에서 자른 말)
- 뽑은 사실로 화면용 요약을 코드가 조립 (AI가 문장을 새로 쓰지 않음)
  - 정책 검색 카드: 항목별 핵심 1~3줄 (`/search` 의 `results[].summary`)
  - 신청 준비 체크리스트: 대상·제외·신청 방법 요약, 조건까지 담은 짧은 서류 이름 (`detail.summary`, `documents[].short_label`)
- 쉬운 말 변환이 이 사실 목록을 "빠지면 안 되는 사실"로 사용 (변환문에 사실의 숫자가 빠지면 다시 변환)
- 결과: P001, 더미 D001~D004 (`data/policy_facts/`, 아직 `verified: false`)

### 미완성·보완 필요 사항
- P001 외 정책은 변환 전
- 일부 항목(예: L1 서류)에 표현만 다른 반복 문장이 남아 있음
- 통과까지 3~4번 재시도해서 변환 한 번에 시간·비용이 듦
- 카드에 올릴 핵심 구절 선택은 AI 판단이라 사람 검수 필요 (예: P001 카드에 "2년 이상 연속 보호"가 빠짐)

### 기술적 개선 방안
- 조건 누락률을 자동 검사 결과로 기록해 평가 지표로 활용
- 변환 결과를 미리 저장(속도·비용 절감), 쉬운 단계(L1·L2)만 큰 모델 사용

## 3. 신청서 작성 도우미·공고 검색

### 구현 현황
- 신청서 파일(PDF·HWP·HWPX)이나 URL → 작성 항목·유의사항 JSON (`data/forms/`)
- 공고 페이지 주소를 넣으면 첨부파일 중 신청서로 보이는 파일을 골라 내려받음
- 공공데이터포털 "대한민국 공공서비스(혜택) 정보" API로 공고 검색 (`--search`)
- 모델이 만든 항목은 원문에 실제로 있는지 검사하고, 사람이 대조한 뒤 `checked: true`로 바꾸는 흐름
- 테스트: 29개 통과

### 미완성·보완 필요 사항
- 공고 검색 API는 키가 없어 실제 호출을 확인하지 못함

## 4. AI 상담·롤플레잉 (`src/coach/`)

### 구현 현황
- 상담 메시지를 정책 질문과 고민 상담으로 나눠, 정책 질문은 정책 검색(RAG)으로 넘김
- 성장 단계별 상담 답변: 아동은 아주 쉬운 말로 2~3문장, 청소년은 작은 행동 하나 제안, 청년은 현실적인 다음 단계
- "더 쉽게 말해 줘"는 앞 답변을 더 쉬운 말로 다시 말함
- 롤플레잉: 상황(집주인 통화, 면접 등)의 상대 역할. 대사 흐름을 참고하되 사용자 말에 먼저 반응하고, 흐름이 끝나면 마무리
- 서류 문장 다듬기 (문장 수가 달라지면 원래 문장 유지)
- 안전 장치: 위기 표현은 AI 전에 키워드로 걸러 도움 연락처 안내, 금액·자격 단정 답변은 고정 안내로 교체, 반말 끝말은 해요체로 보정, 개인정보는 AI에 보내지 않음
- `.env`의 `LLM_MODE`로 목 함수(`mock`)와 실제 AI(`real`) 전환 (`src/backend/app/llm_client.py`)
- 테스트: 27개 통과

### 미완성·보완 필요 사항
- 상담 답변 품질 평가 전 (단계별 말투·길이, 위기 상황 대응)
- 롤플레잉 피드백(잘 챙긴 것·빠뜨린 것)은 아직 키워드 규칙이라 AI가 쓰지 않음

## 5. 정책·지원 데이터 수집 (계획)

### 미완성·보완 필요 사항
- 정책·지원 데이터 자동 수집 기능 없음

### 기술적 개선 방안
- 공공데이터 API(공공서비스 혜택 정보)·공고 페이지에서 정책을 가져와 정책 데이터 형식으로 자동 정리
- 출처·수집일 자동 기록, 내용이 바뀐 정책 감지
- 기존 공고 검색(`src/formguide/search.py`)을 확장

## 6. 향후 개발 일정 (우선순위 순)
1. 쉬운 말: 반복 문장 정리 및 재시도 횟수 줄이기
2. 정책·지원 데이터 수집 기능 개발
3. 쉬운 말·정책 요약: 나머지 정책 변환, 사람 검수
4. RAG·쉬운 말·상담 정량 평가 및 보완 (하이브리드 검색 기준값 조정 포함)
5. 공고 검색 API 실제 호출 확인

## 부록: 자주 쓰는 명령 (src 폴더에서, 백엔드 가상환경)

```bash
# 검색 인덱스 만들기 (real 모드 전에 한 번)
backend/.venv/Scripts/python -m rag.index

# 질문 하나로 RAG 답변 확인
backend/.venv/Scripts/python -m rag.try_search "자립수당은 얼마나 받을 수 있어?"

# 정책 핵심 사실·카드 요약 → data/policy_facts/P001.json (쉬운 말 변환 전에)
EASYTEXT_MODEL=gpt-4o backend/.venv/Scripts/python -m easytext.facts P001 --judge

# AI 상담·롤플레잉 대화 확인 (서버·DB 없이)
backend/.venv/Scripts/python -m coach.try_chat --stage child
backend/.venv/Scripts/python -m coach.try_chat --roleplay landlord

# 쉬운 말 변환 (단계 선택, 2차 검수 포함) → data/easy_text/P001.json
EASYTEXT_MODEL=gpt-4o backend/.venv/Scripts/python -m easytext.convert P001 --levels L1 L2 --judge

# 신청서 → 작성 항목 JSON
backend/.venv/Scripts/python -m formguide.build "신청서.pdf" --policy-key P001 --form-id P001-apply
```

API 키는 `.env`에만 넣고, `.env.example`이나 다른 파일에는 넣지 않습니다.
