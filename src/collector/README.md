# 정책·지원제도 자동 수집 (collector)

자립준비청년이 받을 수 있는 정책·장학금·주거·취업 같은 지원제도를 모아 **앱 기본 데이터 형식(`data/policies/policies.json`, docs/db-schema.md 6장)** 으로 바꿔 넣습니다.
`db/seed.py` 와 같은 검사를 통과해야 저장하므로, 배포 때 시드·검색 인덱스(`rag.index`)가 그대로 읽습니다.

| 수집기 | 어디서 | policy_key | source_type |
|---|---|---|---|
| `python -m collector` | 정부24 공공서비스 API (공공데이터포털) | `G001` … | `api` |
| `python -m collector.web` | 믿을 만한 기관 누리집 (`trusted_sources.json`), OpenAI 웹 검색 + 원문 대조 | `W001` … | `crawler` |

## 실행 (src 폴더에서, 백엔드 가상환경)

```
# 정부24 (.env 의 DATA_GO_KR_SERVICE_KEY 필요)
backend\.venv\Scripts\python -m collector --dry-run --limit 5     # 처음엔 보고서만 보고 확인
backend\.venv\Scripts\python -m collector                         # 기본 검색어 전체 → 저장
backend\.venv\Scripts\python -m collector 장학금 자립               # 검색어 지정
backend\.venv\Scripts\python -m collector --reprocess             # API 없이 저장한 원본으로 다시 변환 (규칙을 고친 뒤)

# 믿을 만한 기관 웹 수집 (.env 의 OPENAI_API_KEY 필요)
backend\.venv\Scripts\python -m collector.web --dry-run 장학금
backend\.venv\Scripts\python -m collector.web                     # 기본 주제 전체 → 저장
backend\.venv\Scripts\python -m collector.web --urls https://www.kosaf.go.kr/...   # 이 페이지만
```

## 한 번에 갱신 · 주기 실행 (`pipeline.py`, `.github/workflows/update-policies.yml`)

```
backend\.venv\Scripts\python -m collector.pipeline --dry-run      # 무엇이 바뀔지만
backend\.venv\Scripts\python -m collector.pipeline                # 수집 → 쉬운 말 변환 → 노출 반영 → 시드 검사 → 보고서
backend\.venv\Scripts\python -m collector.pipeline --reprocess    # 수집 API 없이 저장한 원본으로
```

- 수집이 실패하면(한도 초과 등) 멈추고 파일은 그대로. 변환은 새로 들어왔거나 원문이 바뀐 것만, 예상 비용이 `--max-won`(기본 3,000원)을
  넘으면 그만큼만 하고 나머지는 다음 실행으로. 검사에 실패한 변환은 노출하지 않는다. 보고서: `data/collected/pipeline_report.md`
- 주기 실행: GitHub Actions 가 **매주 월요일 03:00** 이 명령을 돌리고, 바뀐 데이터가 있으면 develop 으로 PR 을 연다 (설명 = 보고서).
  브랜치 `auto/policy-update` 하나에 매번 덮어쓴다 (안 합친 PR 이 쌓여 서로 충돌하지 않게). 워크플로 파일이 main 에 있어야 예약 실행이 돈다.
  손으로: Actions → "정책 데이터 자동 갱신" → Run workflow. 처음 한 번 저장소 설정 필요: Secrets 에 `OPENAI_API_KEY` ·
  `DATA_GO_KR_SERVICE_KEY`, Actions → General → "Allow GitHub Actions to create and approve pull requests"
- PR 을 합치면 Render 가 다시 배포하며 검색 색인(`rag.index`)을 새로 만들고, 서버를 켤 때 `db.seed --dummy-action keep` 이
  `policies.json` 을 DB 에 넣은 뒤 `db.demo_seed` 가 P001 · 더미 노출을 다시 맞춘다 (`render.yaml`, 11/23 배포 담당 확인).
  시드가 실패해도 이전 정책으로 서버는 켠다

저장하는 파일
- `data/policies/policies.json`: 합친 정책 (사람이 쓴 정책은 바꾸지 않음)
- `data/collected/report.md`, `web_report.md`: **사람이 확인할 것** (새로·바뀜·넣지 못함·분야·지역·버린 칸)
- `data/collected/keys.json`, `web_keys.json`: 수집 대상 → policy_key (한 번 정한 키는 바뀌지 않음)
- `data/collected/gov24/{서비스ID}.json`: 정부24 원본 (대조용)

## 형식 맞추기 (data/policies/README.md 작성 기준)

- 칸 이름·코드값(`category`·`region`·`source_type`)은 db-schema.md 그대로. `checked_at` 은 수집한 날
- `original_text` 는 P001 과 같은 머리말 형식: `[출처 A: 정부24]` → 주소 → `[지원대상]` `[지원내용]` `[신청방법]` `[신청서류]` …
  (검색 청크·신청 안내 청크가 P001 과 똑같이 만들어짐)
- `required_docs` 는 `{name, condition}`. "위임장 (대리 신청 시)" → 이름 `위임장`, 조건 `대리 신청 시`
- `required_docs` 는 정부24 `구비서류` + `본인확인필요구비서류` ("해당없음"은 뺌). `공무원확인구비서류`는 내는 서류가 아니라 원문에만 남김
  - 줄 구조를 읽는다: `o 제출서류`·`○ 공통서류`·`※ 추가제출서류(해당 대상자)` 는 묶음 제목(서류 아님),
    `6. 자립준비청년` 아래 `- 보호종료확인서` → 조건 "자립준비청년", `신혼부부 : 혼인관계증명서` → 조건 "신혼부부",
    `- 참여신청서, 개인정보동의서` → 서류 2개 (괄호 안 쉼표는 나누지 않음)
- `support_amount` 는 지원내용에 금액 표현이 **하나일 때만** 그대로 ("월 50만 원"). 여러 개면 비운다 — 이어 붙이면 뜻이 틀어짐 (디딤씨앗통장 "월 10만 원, 10만 원, 월 50만 원" 의 50만 원은 추가 적립 한도). 금액이 없는 제도(사례관리 · 멘토 등)도 `null`
  - 예외: 여러 개여도 한 사람이 받는 총액이 분명하면 그 총액 (자립정착금 분할 지급). "1,500만원(당해 1,000만원 + 익년 500만원)" · "22년 이후 15백만원" · "1회 1,000만원 / 2회 500만원" → 1,500만 원. "1천5백만원" · "천만 원"도 숫자로 읽는다. 월 · 연 금액이 섞이면 비운다
  - 금액 칸만 바뀌면(뽑는 규칙을 고친 뒤) 원문은 그대로라 쉬운 말 검수 상태는 지킨다
- 분야: 법률 지원("소송 · 법률")은 '자립'으로 (법률상담의 '상담'이 '의료'에 걸리던 것). 지역: 기관 이름 앞 "(재) · 재단법인"을 떼고 찾음 ("(재)인천인재평생교육진흥원" → 인천)
- `age_min`·`age_max` 는 `null`. 정부24 지원조건 코드(`JA0110`·`JA0111`)는 뜻이 확인되지 않아 쓰지 않음 (자립준비청년 정책이 17~18 로 옴)
- `easy_text: null`, `easy_text_verified: false` → **쉬운 말 변환·검수 전에는 앱에 보이지 않음**
- 분야는 이름·지원내용 낱말로, 지역은 소관기관(시/도)으로 고르고 고른 이유를 보고서에 남김. 시·군·구 정책은 '확인 필요'
  - 시·군·구 정책은 `region` 을 그 시/도로 넣어 시/도 사용자 모두에게 보이고, 앱 자격 판정은 지역이 '조건 확인 필요'(`needs_check`)로 나온다 (`app/rules.py` `is_local_agency`)

## 하루 한도

일시적 오류(HTTP 429 · 5xx · 시간 초과)는 1초 → 2초 → 4초 쉬었다 다시 묻는다. 그래도 안 되는 상세는 그 서비스만 건너뛰고 보고서 '넣지 못함'에 남기며,
전에 넣은 정책은 그대로 두고 '이번 수집에 없음'으로도 보지 않는다. 목록(serviceList)이 끝내 안 되면 수집을 멈춘다 (목록이 빠진 채로 합치지 않게).

공공데이터포털 키는 하루 요청 수 한도가 있다 (넘으면 HTTP 429 "트래픽 허용 횟수를 초과"). 전체 수집 한 번에 약 600번 요청한다
(목록 + 상세 257 + 지원조건 95). 같은 키를 쓰는 다른 프로젝트와 한도를 함께 쓴다.
한도를 다 쓴 날이나 변환 규칙만 고쳤을 때는 `--reprocess` (확인일 `checked_at` 은 그대로 둠).

대상 칸(`target_description`)은 지원대상 + `선정기준: …`. 정부24 는 선정기준 칸에 지원대상을 그대로 되풀이하는 일이 많아
같은 내용이면 붙이지 않는다 (11/23: 5개 정책에 대상 문단이 두 번 들어가 쉬운 말 검사가 "같은 값을 두 번 쓰라"고 하던 것).

나이(`age_min` · `age_max`, 만 나이 · 양 끝 포함)는 대상 칸에 지원자 나이를 분명히 쓴 것만 넣는다 (`convert.pick_ages`).
"18~39세" · "만 18세 이상" · "만 18세 미만" 은 넣고, 아래는 비운다 (비면 앱은 나이 제한 없음으로 봐서 더 많이 보임 — 잘못 넣어
받을 수 있는 사람에게 안 보이는 것보다 안전):
- 시점 표현 "만 18세 이후 보호가 종료된" · "18세가 된 때로부터", 예외 "18세 이상인 경우에도 …" · "보호연장 가능" · "조기"
- 나이 없는 대상과 '또는'으로 묶임, 대상 묶음(○) 중 나이가 없는 것이 있음, 각주(`*`) 안의 나이, 자녀 나이, 7세 미만 상한
- 정부24 지원조건의 대상연령(`JA0110` · `JA0111`)은 쓰지 않는다: 원문과 반대(G010 '18세 이상'인데 0~17)이거나
  자립정착금 대부분이 17~18 · 18~19세처럼 원문보다 좁아 20대 자립준비청년을 숨기게 된다 (11/23 95개 대조)
원문에 분명한 나이가 없으면 대상 종류로 법에 정해진 범위를 쓴다 (`convert.infer_ages`, 웹 수집도 같은 규칙 `convert.policy_ages`):
- 보호 중인 아동(가정위탁아동 · 보호대상아동 · 시설 입소 · 생활 아동 · 초중고 …) → **~17세** (아동복지법상 아동: 18세 미만, `CHILD_AGE_MAX`).
  18~24세 보호연장 청년은 이 정책들에서 빠진다
- 보호가 끝난 청년(보호종료 · 퇴소 · 종결 · 자립준비청년 · 자립정착금 …) → **18세~** (원문이 18세 · 만기 · 연령초과라고 할 때),
  아니면 **15세~** (조기 보호종료 · 퇴소 예정 · 말 없음 — 보호종료는 아무리 일러도 15세 이후). 상한은 비움 (보호종료 나이가 18~25세로 달라)
- 비움: 둘이 섞임 · 다른 대상(수급자 · 장애인 · 신혼부부 …)이 함께 · 대학 진학 지원 · 지원내용에 보호종료자 지원이 섞임 · 대상 종류를 모름
나이는 분야 · 지역처럼 사람이 고친 값만 지키고, 아니면 규칙 값으로 다시 쓴다 (`auto_values.json`).

수집한 정책이 서비스에 나오려면 쉬운 말 변환(`python -m easytext.batch --collected`) → 노출 칸 반영(`python -m easytext.publish`)
→ 시드. 내용이 바뀐 정책은 `easy_text_verified` 가 false 로 돌아가므로 같은 순서로 다시.

## 대상 고르기 (정부24)

검색어(가정위탁·아동복지시설·자립지원)는 앱 사용자가 아닌 사람 대상 제도도 많이 가져옵니다 (실제 257건 중 161건).
`convert.relevance` 가 이름·지원대상 낱말로 고르고, 뺀 것은 보고서 '대상이 달라 뺌'에 이유와 함께 남깁니다.
- 넣음: 이름에 자립준비청년·보호종료·퇴소아동·보호대상아동·가정위탁아동 등이 있거나, 지원대상에 있고 이름이 자립·장학·주거·취업 제도
- 뺌: 다른 대상(입양·장애인·한부모·가정폭력·노숙 …, 이름에 '자립'이 있어도), 사용자가 신청하지 않는 지급·일반 감면(위탁부모 양육보조금·위문금·요금 감면 …)

## 같은 제도 거르기

이름(괄호·띄어쓰기 무시)과 기관(부서 빼고)이 같으면 같은 제도로 보고 넣지 않습니다.
- 보건복지부 "자립준비청년(보호종료아동) 자립수당 지급" = P001 → 넣지 않음
- 시·군·구마다 같은 이름의 "자립정착금 지원"은 기관이 달라 따로 넣음

## 합치는 규칙

- 분야(`category`) · 지역(`region`): 수집기가 마지막으로 넣은 값을 `data/collected/auto_values.json` 에 남긴다. 지금 값이 그것과 같으면(사람이 안 고쳤으면) 분류 규칙을 고친 뒤 새 값으로 바꾸고(보고서 '분야 · 지역 규칙이 바뀌어 새로 고름'), 다르면(사람이 고쳤으면) 그대로 둔다

- 사람이 쓴 정책(`source_type: manual`, 예: P001)은 절대 바꾸지 않음
- 내용이 같으면 확인일(`checked_at`)만 바꿈. 사람이 고친 값(나이·분야·지역·`is_active`…)은 그대로
- 내용이 바뀌면 새 내용으로 쓰고 `easy_text_verified` 를 `false` 로 되돌림 (다시 검수할 때까지 숨김)
- 이번 수집에 안 나온 정책은 지우지 않고 보고서로만 알림

## 웹 수집을 믿을 수 있게 하는 장치

1. **기관 목록**: `trusted_sources.json` 의 공식 누리집만 (go.kr 정부·지자체, 아동권리보장원·LH·HUG·서민금융진흥원, 사랑의열매, 초록우산·아름다운재단). 검색도 이 도메인 안에서만 하고, 받은 페이지가 목록 밖 주소로 넘어가면 버림
2. **원문 대조**: AI 가 뽑은 칸마다 원문 인용을 받아, 인용(또는 값 자체)이 페이지에 그대로 없거나 · 원문에 없는 숫자가 있거나 · 낱말 대부분이 원문에 없으면 그 칸을 버림. 정책명·지원대상·지원내용·신청방법 중 하나라도 버려지면 그 제도는 넣지 않음. 서류도 원문에 그대로 있는 이름만
3. **지금 신청할 수 있는 것만**: 신청기한 날짜가 모두 지났거나 종료·결과 발표 글이면 넣지 않음
4. **겹침**: 이미 있는 정책(정부24·사람이 쓴 것)과 같은 제도면 넣지 않음 (위 '같은 제도 거르기')
   - 시·군·구청 누리집인데 지역을 못 찾으면 보고서에 'region 확인 필요'
5. **사람 확인**: `crawler`·`easy_text_verified: false` 로 들어가고, 보고서의 출처 주소를 열어 확인한 뒤 검수

새 기관은 공식 누리집인지 확인한 뒤 `trusted_sources.json` 에 넣습니다 (블로그·카페·뉴스·광고 사이트는 넣지 않음).
검색 모델은 `gpt-5-mini` 입니다. 도메인 제한(`filters.allowed_domains`)이 `gpt-4.1-mini` 에서는 400 오류로 안 됩니다. 페이지 칸 뽑기는 `gpt-4.1-mini`.
